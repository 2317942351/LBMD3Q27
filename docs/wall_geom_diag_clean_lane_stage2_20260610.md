## Interpretation

The direct formula-level source is:

```text
PhaseF_wall = pf_f + tan(pi/2 - radAngle) * grad_tangent * 2h
```

At `radAngle=11d`, the multiplier is about `5.144554`. The diagnostic run
shows that this multiplier is large enough to produce wall ghost `PhaseF>1`
immediately in both flat and curved geometries. The prior long theta030
radAngle011 run showed the same mechanism growing during relaxation, with
boundary ghost values reaching much larger values by later frames while the
fluid phase stayed near-bounded.

The current evidence therefore rejects these explanations as primary causes:

```text
wrong q27/geometric binary
wrong PhaseField_h/l range
missing 0.5 in sphere initializer
surface-energy fallback as the direct source for audited overrun cells
curvature alone as the only cause
```

The supported explanation is:

```text
low radAngle makes the normal geometric branch's positive tangent-gradient
extrapolation large; curved geometry can sharpen the peak through discrete
normal/neighbor layout; these ghost values can then contaminate near-wall
GradPhi/mu/surface-force and contribute to mass/shape drift.
```

## Fix Direction Audit

Do not treat a hidden clamp as a physical fix. A clamp may be useful only as a
separately labeled localization test.

The next defensible solution path is:

```text
1. Stop using very low radAngle as a calibration shortcut for theta030 unless
   the wall ghost health gate is passed.
2. Add a near-equilibrium cap-on-sphere initializer and compare it against the
   current free-sphere tangent initializer, because the current initial state
   is far from a theta030 cap on a sphere.
3. Implement a separate explicitly named diagnostic variant for bounded or
   profile-consistent wall reconstruction, then run the same flat/curved

4. Only if the diagnostic variant reduces wall ghost overrun without worsening
   fluid-only mass drift, rho drift, Mach, nonfinite, and local contact angle,
   promote it to a candidate physics fix for longer PRE sphere runs.
```

Candidate implementation families to test:
